# GitHub PR タイトル・説明自動更新

指定されたPR番号の変更差分を分析し、包括的なタイトルと説明文を自動生成してPRを更新します。

## 実行手順

### 1. 前提条件の確認

まず、GitHub CLIがインストールされ、認証されているか確認してください：

```bash
gh --version
gh auth status
```

もし認証されていない場合は、以下のコマンドで認証してください：
```bash
gh auth login
```

### 2. PR情報の取得

PR番号: `$ARGUMENTS`

以下のコマンドを実行して、PR情報を取得します：

```bash
# PR基本情報の取得
gh pr view $ARGUMENTS --json number,title,body,author,baseRefName,headRefName,state,url

# PRの変更差分を取得（詳細な差分）
gh pr diff $ARGUMENTS

# PRのファイル一覧を取得
gh pr view $ARGUMENTS --json files --jq '.files[].path'

# PRのコミット履歴を取得
gh pr view $ARGUMENTS --json commits --jq '.commits[] | "\(.oid[0:7]) \(.messageHeadline)"'
```

### 3. 変更内容の分析

取得した情報から以下を分析してください：

**変更の種類を特定：**
- 新機能追加（feat）
- バグ修正（fix）
- リファクタリング（refactor）
- ドキュメント更新（docs）
- スタイル変更（style）
- テスト追加/修正（test）
- パフォーマンス改善（perf）
- ビルド・CI関連（build/ci）
- その他（chore）

**変更の影響範囲：**
- 影響を受けるモジュール/コンポーネント
- 変更されたファイル数と行数
- 破壊的変更の有無

**技術的な詳細：**
- 主要な変更内容
- アーキテクチャへの影響
- 依存関係の変更

### 4. PRタイトルの生成

Conventional Commits形式で簡潔で明確なタイトルを生成します：

**フォーマット：**
```
<type>(<scope>): <short summary>
```

**ガイドライン：**
- 50文字以内
- 日本語または英語（プロジェクトの慣例に従う）
- 動詞から始める
- 具体的で分かりやすく

**例：**
- `feat(auth): ユーザー認証にOAuth2.0を実装`
- `fix(api): レート制限エラーのハンドリングを修正`
- `refactor(database): クエリパフォーマンスを最適化`

### 5. PR説明文の生成

以下のセクションを含む包括的な説明文を生成します：

#### 📋 概要（Summary）
- 変更の目的を3-5文で簡潔に説明
- ビジネス価値やユーザーへの利点を明記

#### 🎯 背景・目的（Background & Motivation）
- なぜこの変更が必要なのか
- 解決しようとしている課題や問題
- 関連するIssue番号があれば記載（例：`Closes #123`, `Relates to #456`）

#### 🔧 変更内容（Changes）
主要な変更を箇条書きで詳しく説明：
- 追加された機能や修正内容
- 変更されたファイルの役割
- 技術的な実装の詳細
- アーキテクチャや設計の変更点

#### 🧪 テスト（Testing）
実施したテストと結果：
- ユニットテストの追加/更新
- 統合テストの実施
- 手動テストの手順と結果
- エッジケースの考慮

#### 📸 スクリーンショット・デモ（Screenshots/Demo）
該当する場合：
- UI変更のスクリーンショット
- ビフォー/アフター比較
- 動作デモのGIFやビデオリンク

#### ⚠️ 破壊的変更（Breaking Changes）
該当する場合：
- 後方互換性のない変更
- マイグレーション手順
- 影響を受けるAPIやインターフェース

#### 📝 備考（Notes）
- レビュー時の注意点
- 今後の課題や改善点
- 関連する技術的な背景情報
- パフォーマンスへの影響

#### ✅ チェックリスト（Checklist）
- [ ] コードレビューの準備完了
- [ ] テストが追加/更新され、すべて成功
- [ ] ドキュメントが更新済み
- [ ] 破壊的変更がある場合、マイグレーションガイドを作成
- [ ] CIチェックがすべて成功

### 6. PRの更新

生成したタイトルと説明文を使って、PRを更新します：

```bash
# 生成したタイトルを変数に格納
TITLE="生成したタイトルをここに"

# 生成した説明文を変数に格納（複数行の場合）
read -r -d '' BODY << 'EOF'
生成した説明文をここに
（複数行可能）

## 📋 概要
...

## 🎯 背景・目的
...
EOF

# PRを更新（タイトルと説明文を同時に更新）
gh pr edit $ARGUMENTS --title "$TITLE" --body "$BODY"

echo "✅ PRのタイトルと説明文を更新しました"

# 更新されたPRを確認
gh pr view $ARGUMENTS
```

**注意事項:**
- タイトルと説明文に特殊文字（`"`, `$`, `` ` ``など）が含まれる場合は、適切にエスケープしてください
- 説明文が非常に長い場合（数千文字以上）は、問題なく動作します
- シェルの変数展開を避けるため、`BODY`の定義では `'EOF'` を使用しています

### 7. 確認と完了

最後に、更新されたPRのURLを表示して完了を報告：

```bash
echo "✅ PRが正常に更新されました！"
gh pr view $ARGUMENTS --web
```

## 重要な注意事項

1. **権限の確認**: PRを更新する権限があることを確認してください
2. **既存内容の保護**: 既存のPR説明に重要な情報がある場合は、それを保持するか確認してください
3. **レビュー中の場合**: レビュー中のPRを更新する場合は、レビュアーに通知してください
4. **差分の解釈**: 変更が大規模な場合は、主要な変更に焦点を当ててください
5. **日本語/英語**: プロジェクトの言語規約に従ってください

## トラブルシューティング

- **GitHub CLIが見つからない**: `brew install gh` または https://cli.github.com/ からインストール
- **認証エラー**: `gh auth login` で再認証
- **PR番号が無効**: 正しいPR番号を確認してください
- **リポジトリが見つからない**: 正しいディレクトリで実行しているか確認
- **"Projects (classic) is being deprecated" エラー**: GitHub CLIを最新版に更新（`gh extension upgrade gh`）するか、コマンド内でGraphQL APIを直接使用する方法に変更されています

/update-pr 123
